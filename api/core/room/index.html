Gotchas

  • deleted is a soft delete: hidden from the list, retained locally after remote deletion is acknowledged. No automatic cleanup is implemented; remote hard deletes do not remove other devices' existing local rows through the incremental pull.

  • lastUpdated and lastSynced are device-clock milliseconds used in pending-change detection; both are transmitted to/from Firestore. serverUpdatedAtNanos is the server write timestamp used by the pull cursor. See metadata and algorithm.

  • getSyncCursor includes soft-deleted rows because their server timestamps are already stored. It is a timestamp-only cursor, with interruption/tie limitations described in the guide.

  • Version 2 has no registered migration from version 1 and uses destructive fallback. Upgrades can erase unsent local changes. Same-version schema-integrity errors are a different failure path; see schema changes.
