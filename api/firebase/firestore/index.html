Gotchas

  • Current Home screens observe Room through HomeRepository; that repository calls this source during synchronization. No current screen queries Firestore directly.

  • The repository upload mapping leaves serverUpdatedAt as null: Firestore substitutes its timestamp for a null @ServerTimestamp property, and that server clock — never lastUpdated, which belongs to the writing device — is what orders pullJetpacks. See Data Layer.

  • It is not a constructor parameter, so :data never needs com.google.firebase.Timestamp on its compile classpath. This module declares the SDK with implementation, not api, and moving the property into the constructor would break that boundary.

  • Rule rejection fails the remote operation during sync; the worker logs errors and may retry. A successful local repository write does not establish remote acceptance.

  • Pull uses default-source get() and a strict server-timestamp filter. Cached results do not establish server completeness; missing timestamp fields are excluded, and equal-timestamp interruption can skip records. Remote hard deletes supply no deletion feed. See delivery limitations and upgrade requirements.
