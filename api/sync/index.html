:sync

Purpose: Implements SyncManager from :data and schedules a WorkManager job. SyncWorker collects the Syncable repository implementation in :data, which pushes then pulls.

Gotchas

  • ExistingWorkPolicy.KEEP ignores a request while matching unfinished work exists. It does not schedule another pass for writes made after the repository's pending snapshot.

  • No custom backoff is set: the three retry delays nominally start at 30, 60, and 120 seconds. Constraints/system scheduling can delay execution. isSyncing is true only for RUNNING work.

  • The worker catches Exception, including cancellation; it does not explicitly rethrow cancellation. See progress, retries, and errors.

  • Foreground configuration is incomplete: runtime ForegroundInfo has no service type, and the reviewed merged manifests lack the data-sync service type/permission. A separately reviewed fix and device verification are needed; see foreground diagnostics.

  • The only configured work constraint is NetworkType.CONNECTED. There is no battery/storage/idle constraint.

  • The actual push-then-pull sync algorithm lives in HomeRepositoryImpl.sync() (:data), not here — this module schedules work, collects progress and manages worker retries.
